# Почему у SCAR получилось, а у нас нет (разбор за ночь 8–9 октября 2026)

Вопрос: SCAR учит модель награды только на полных ответах и считает Шепли, спрашивая её о неполных — и это работает. У нас VM, обученная на полных попытках (попарно по судье и R плюс поточечно по исходу), дала в v8 метки Шепли с отрицательной заслугой ANSWER (−0.18) и gain-AUC 0.33. Интуиция: настоящая оценка исхода — сигнал сильнее сравнения, должно было работать лучше. Ниже — что установлено по статьям, по нашим данным v8 и по опытам на OpenRouter (расход за ночь $0.14).

## Что именно делает SCAR (arXiv 2505.20417)

- Модель награды — обычная RLHF-модель: классификатор тональности (IMDB), 1B-модель на 92 тыс. пар предпочтений TL;DR (точность 74 %), готовая 3B-модель на HH. Учится только на полных ответах (TL;DR и HH — попарно).
- Характеристическая функция коалиции: v(S) = r(x, y_S), где y_S — ответ, в котором токены вне S заменены пустыми местами. Модель награды действительно спрашивают о неполном тексте.
- v(∅) = 0 по соглашению, и по аксиоме эффективности сумма заслуг равна r_φ(x, y) — оценке той же модели награды за весь ответ, той самой, которую оптимизирует и разреженный базовый вариант. Плотная награда — перераспределение этой оценки по отрезкам.
- Награда в RL: R_t = KL + α·Шепли + (1 − α)·награда за весь ответ в конце (α = 0.8–1.0).
- Авторы сами оговаривают: метод предполагает, что модель награды осмысленно оценивает неполные тексты, и не подходит, когда награда — проверка только итогового ответа по правилам.
- Задачи: тональность, суммаризация, полезность диалога.

## Настоящие причины расхождения (после адверсариальной проверки отчёта тремя рецензентами)

Сначала поправка к моей первой формулировке: у SCAR сумма заслуг — это не «настоящая награда», а оценка той же обученной модели награды r_φ(x, y) (74 % попарной точности), то есть тоже предсказание. v(∅) = 0 у них — соглашение, а не измерение. Авторы называют заполнение пустыми местами «практическим приближением» к идеалу: «v(S) could represent the expected reward obtained by keeping units in S fixed and sampling remaining units from the current policy» — то есть идеалом они считают дорешивание (наш опыт E3). Структурно наш v8 уже был «как SCAR» (все v от одной модели); единственное отличие — v(∅) бралась из VM, а не ставилась нулём.

**1. Природа награды.** У SCAR награда градуированная и почти аддитивная по тексту (тональность, качество резюме, полезность): у половины текста есть половина качества, и модель награды, обученная на полных ответах, переносится на неполные хотя бы по направлению. У нас награда — бинарная проверка решения, у неполной траектории нет «частичной правильности», ценность шага — вероятность дойти до верного ответа. Авторы SCAR сами исключают такие задачи («rule-based models that only evaluate final answers, e.g. in mathematical reasoning»).

**2. Что именно сломалось в v8 — сумма, а не только деление.** Сумма заслуг кадра Σφ = v(вся) − v(пусто). По меткам v8 средняя Σφ по числу жителей: −0.59 (2), −0.52 (3), −0.29 (4), −0.05 (5), ≈0 (6–8), тогда как калиброванная VM дала бы около нуля везде; corr(Σφ, число жителей) = 0.66. Это завышенная v(пусто) на лёгких задачах, и это парадокс Симпсона: внутри одной сложности сумма удачи и неудачи различает слабо, но в нужную сторону (AUC 0.60–0.69, при 3 жителях интервал исключает 0.5), а объединённо по всем жителям — 0.34. Длина траектории ничего не добавляет к числу жителей (частная корреляция 0.02; моя прежняя цифра 0.26 не воспроизводится и снята).

**3. Деление внутри кадра — слабое и с систематическим знаком против ответа.** Заслуга ANSWER у удач и неудач внутри одной сложности не различается: AUC 0.65 / 0.51 / 0.43 с интервалами [0.47, 0.81], [0.41, 0.60], [0.31, 0.56]; объединённо по 2–4 жителям 0.47 [0.40, 0.54]. Шаг с запросами VM читает слабо (AUC ≈ 0.65 при 3 жителях). При этом в 87 % двухшаговых неудач ANSWER получает меньше, чем запросы (−0.10 против +0.09) — тот самый сигнал «продолжать выгоднее, чем отвечать», который через RM и игру шага доходит до актора.

**4. Проверка ответа недоступна слабой модели (E2).** 40 верных и 40 неверных ответов той же сложности (2–4 жителя), без эталона: qwen-2.5-7b — 0.62 по условию и ответу, 0.60 с траекторией (интервал [0.51, 0.73]; формально чуть выше случайного, 10 из 40 неверных ответов неполны по формату и отвергаются «бесплатно»; с траекторией модель отвергает 72 % всего). gpt-oss-120b с рассуждением до 2500 токенов — 80/80 в обеих постановках (при лимите 600 токенов половина ответов не доходит до вердикта). Проверить ответ значит решить задачу; это по силам рассуждающей модели с бюджетом, не ModernBERT-base на 744 парах (попарная точность 0.65 против 74 % у 1B-модели SCAR на 92 тыс. пар).

**5. Почему «настоящая оценка исхода» сама по себе не решает.** Исход точен для всей попытки, но ничего не говорит о том, какой шаг его обеспечил. Делить его может либо модель, понимающая шаги, либо дорешивание. Якорь (ниже) берёт от исхода ровно то, что в нём есть, — сумму; деление остаётся за VM.

## Чего «заслуживают» подмножества шагов (E3, ваша идея про дорешивание)

30 попыток 1.5B из датасета v8, дорешивание qwen-2.5-7b с новыми промптами, по одному прогону на состояние (удачи: 10 задач на 3 жителей, по одной на 2 и 4; неудачи отобраны проще — 14 на 3 и 4 на 2):

| исходная попытка 1.5B | с нуля | с её первого шага (запросы и результаты подзадач) | принудительный ответ по первому шагу |
|---|---|---|---|
| удачна (n = 12) | 0.58 | 0.42 | 0.17 |
| неудачна (n = 18) | 0.39 | 0.06 | 0.06 |

Отдельно по задачам на 3 жителей: удачи (n = 10) — 0.60 / 0.30 / 0.20; неудачи (n = 14) — 0.36 / 0.07 / 0.00.

Что из этого держится: (а) подмножество действительно не заслуживает метки полной попытки: у удач ценность префикса около 0.3–0.4, а не 1, у пустой коалиции не 0 — но это ценности для 7B; для политики 1.5B «пустая коалиция» — её собственная доля удач (0.22 при 2 жителях, 0.15 при 3, 0.045 при 4), игра относится к политике; (б) префикс неудачной попытки почти безнадёжен (0.06 против 0.39 с нуля; парное сравнение 6:0, p = 0.03) — результаты подзадач 1.5B в нём в основном ложные; (в) «результаты подзадач вредят и удачным попыткам» (0.42 < 0.58) при n = 12 не значимо (p = 0.6); (г) столбец «принудительный ответ» почти дублирует «префикс»: в 23 из 30 состояний 7B с префикса сразу отвечает одним вызовом; (д) дорешивание с нуля стоит в среднем 9 вызовов на состояние (до 45), шумно при одном прогоне; работа Qwen о PRM (arXiv 2501.07301) о том же: метки Монте-Карло неточны, лучше сочетать их с судьёй.

## Что изменено в коде и что это даёт

- **Якорь концов игры** (`rm_anchor`, 2a0d40c): v(∅) = 0 как у SCAR, v(вся) = исход кадра. Честно о его действии: Шепли линеен по v, поэтому якорь сдвигает все заслуги кадра на одну величину (R − Σφ)/m — чинит сумму (пункт 2), но не трогает порядок шагов внутри кадра (пункт 3). На метках v8 после якоря ANSWER наверху остаётся в среднем −0.08 против +0.12 у запросов. Для актора сдвиг суммы и сам по себе был не главным злом: преимущество считается относительно ценности окна с условием задачи, то есть постоянный по задаче сдвиг там вычитается; главное зло — деление против ответа.
- **Метка подзадачи по её собственной правильности** (84454b1): для K&K истина подзадачи-допущения выводится из эталона корня (допущения согласны с эталоном — роли эталона, иначе «contradiction»), как для арифметики было всегда. До этого 93 % строк обучения RM — подзадачи с меткой корня: каждая из 16 подзадач решённой задачи получала сумму заслуг 1 независимо от своего ответа.
- **Обучение VM на коалициях** оставлено, но без пустой коалиции при якоре (она не запрашивается). Оговорка рецензента верна: метка кадра для всех подмножеств в пределе учит v(S) = R и сводит деление к равномерному; при якоре это безопасно (равномерное деление — обычное обучение по исходу), информативное деление остаётся за попарной частью.
- **Контрольное плечо** `rm_split="uniform"`: заслуга = исход/число шагов, без VM. Это честная база для сравнения с игрой VM; предлагаю прогнать её как абляцию.
- **Диагностики деления в логе** (моя прежняя `phi_top_answer_ok/fail` при якоре бессмысленна — разрыв создаёт сам якорь): смотреть на кадрах с исходом 0 наверху — `phi_top_answer_fail` и `phi_top_requests_fail` (хорошее деление ⇒ оба около нуля; v8 дал бы −0.10 / +0.09) и `split_against_answer_fail` — доля кадров, где ANSWER получил меньше запросов (шум ⇒ ≈ 0.5; v8 ⇒ 0.87). Плюс `v_full_top_ok` против `v_full_top_fail` — оценки самой VM без якоря.
- **Чего нет**: у SCAR в RL остаётся слагаемое (1 − α)·награда за весь ответ на последнем токене (α = 0.8 в двух задачах из трёх); у нас в воображении награда — только RM. Если деление останется шумным, добавить терминальную награду по исходу — следующий кандидат, вместе с валидацией деления дорешиванием на 20–30 кадрах.
